# Stepped Agent Line: Security Audit (2026-11-23)

> Free bot audit by Grok Bot for LG Studios before the planned Base deploy. Base commit `main@6202e3c`; fixes on branch `audit-2026-11-23`.
> Nothing was deployed or broadcast, and no keys were read. Anvil fork tests used a local Base fork (chain 8453) on port 8644.

## 1. Summary

| Severity | Count | Fixed | Acknowledged |
|---|---|---|---|
| Critical | 0 | – | – |
| High | 1 | 1 (H-1) | – |

| Low | 3 | – | 3 |

**Key result:** before the fix, an agent could climb the whole credit ladder in one block by borrowing and repaying 1 wei (USDC base unit) in a loop. Each loop counted as an "on-time full repayment", so the agent reached `maxCap` and inflated its public `onTimeCount` for gas only. It could then borrow `maxCap` and never repay. That defeats the product's core promise ("exposure grows only with a proven repayment record"). It is fixed and has regression tests.

**Verdict: ready to deploy with notes** (see section 5).

## 4. Findings

### [H-1] Dust or same-block borrow/repay loops climb the ladder to `maxCap` and inflate `onTimeCount` (Fixed)

**Where:** `SteppedAgentVault.repay` → `_stepUp` (main: lines 291-317, 371-379).

**Impact:** any full repayment at or before `dueDate` stepped the cap, however small the cycle or however recently the last step happened. The agent (or anyone acting with its key) can run `borrow(self, 1) → repay(self, 1)` N times in a single transaction for gas only (fractions of a cent per loop on Base). That reaches `maxCap`, then `borrow(maxCap)` drains `maxCap` instead of `starterCap`. The backer loses up to `maxCap − starterCap` more than intended. Other apps reading `creditHistory()` also see a fake on-time record. A same-block full-size loop works the same way, since the agent repays with the USDC it just borrowed.

**PoC:** `test_H1_dustLoopCannotClimbLadder`: on main, 99 dust loops took the cap from 100 to 10,000 USDC (FAIL on main, PASS on the fix). `test_H1_fullSizeSameBlockLoopStepsAtMostOnce`: on main, 10 loops gave cap 1,100 (FAIL on main, PASS on the fix).

**audit-kb:** Gearbox, "Flashloan protection bypass through debt increase and account closure within the same block" (solodit:53771); Parallel V3, "globalCreditLimit can be bypassed" (BailSec).

**Fix:** a cycle earns a step (and an on-time count) only if
1. its **peak debt reached 50% of the current cap** (`MIN_USAGE_BPS = 5000`, tracked in the new public `cyclePeak[agent]`, which resets when a cycle closes, on `clearDefault`, and on a fresh `openLine`), **and**
2. **at least one `term` has passed since the last step** (`lastOnTimeAt + term`).

Other on-time full repayments close the cycle without a step. A fuzz test (`testFuzz_H1_stepsRateLimited`, 1000 runs) asserts `onTimeCount ≤ 1 + elapsed/term`. `test_H1_honestCyclesStillStep` and `test_H1_usageThreshold` cover honest use and the boundary.

**Residual (by design):** an agent can still borrow 50% and simply hold or repay it, earning at most one step per term. No on-chain credit line can tell idle repayments from real work, so set `term` and `stepSize` with that in mind (for example, don't use a 1-day term with large steps).

**Behaviour change:** existing unit and fork tests that stepped in the same block or below 50% usage were updated (larger borrows, plus a `warp(TERM)` between cycles). `borrow` costs one extra SSTORE when a cycle's peak rises. The `getLine`, `getHistory` and `creditHistory` ABIs are unchanged; `cyclePeak`, `MIN_USAGE_BPS` and `BPS_DENOMINATOR` were added.

### [L-1] Defaults are only recorded if someone calls `markDefault` before repayment (Acknowledged)
`markDefault` / `repay`. An agent past `dueDate + grace` that repays before anyone marks it gets only `lateCount += 1`, with no freeze and no `defaultCount`, and keeps its tier. PoC: `test_L1_lateRepayAfterGraceWithoutKeeperLeavesNoDefault`. **Recommendation:** the backer (or a keeper/routine) should call `markDefault` when grace ends.

### [L-2] Revoked lines keep their tier and an open cycle (Acknowledged)
`openLine` on a revoked, non-frozen line keeps `currentTier` and `dueDate`. This is intended ("Revoked lines keep their tier"), but if you revoke because the agent's key leaked, a re-opened line is still at the high cap. Lower the ladder with `openLine` params if needed.

### [L-3] The owner can withdraw all liquidity while lines are open (Acknowledged)
`withdraw` has no reserve. This is by design (backer-funded), but agents can then hit `InsufficientLiquidity` mid-cycle.

### Info
- **I-1** USDC blacklist: `borrow` to a blacklisted `to` reverts, and a blacklisted payer can't `repay` (anyone else can). Repayments go to the vault, not to a lender, so the "lender blacklisted blocks repay → forced default" class (Sherlock Cooler H-4, solodit:6281; Predict.fun M-1, solodit:41806) does **not** apply. If the vault itself were blacklisted, everything would freeze (Circle-level risk).
- **I-2** `epoch` and `currentTier` use `unchecked` increments. Overflow needs 2³² calls, which isn't practical.
- **I-3** `isRecipientAllowed` returns true for any non-zero address on a line without an allowlist, even an inactive one. It's a view helper only.
- **I-4** `setGuardian(0)` is allowed (used to unset the guardian). The Slither missing-zero-check result is intended.
- **I-5** The contract still has the `PROTOTYPE - NOT AUDITED` NatSpec. Update it at deploy time if you want.

## 5. Ready to deploy?

**Yes, with notes.** H-1 is fixed and tested. Before going live on Base:
1. Pick `term` / `stepSize` so that one step per term is acceptable exposure growth.
2. Run a keeper/routine (or check by hand) to call `markDefault` when grace ends (L-1).
3. Get Lef's go for the deploy (`CONFIRM_MAINNET=yes`).
